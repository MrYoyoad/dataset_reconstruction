## Process
1. **Identify the audience** — supervisor? Committee? Conference? Adapt tone and detail level.
2. **Check existing material** — read STATUS.md, LESSONS_LEARNED.md, relevant notes/ files first.
3. **Draft** — write clear, concise academic prose. Lead with the contribution, then the method.
4. **Review** — check for:
   - Claims that aren't supported by our experiments
   - Stale numbers (grep results/ for current values)
   - Missing citations for key claims
5. **Save** — put output in the appropriate location (notes/, docs/, or inline response).

## Style
- Read STYLE_GUIDE.md before generating any document (docx, pptx, LaTeX)
- Active voice preferred
- Quantify claims: "SSIM improved by 0.12" not "results improved significantly"
- Connect everything to the thesis narrative: LoRA adapters encode enough information to reconstruct training data
